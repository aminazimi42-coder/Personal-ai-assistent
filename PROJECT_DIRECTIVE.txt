PHASE 8 — CODE RETRIEVAL & TOKEN EFFICIENCY This is an approved core
product capability for END USERS, not merely an agent-development
feature. Goal: when a user asks the Assistant to work with
code/projects, retrieve only relevant code rather than sending whole
repositories to the LLM. Pipeline: USER REQUEST → INTENT ANALYSIS → CODE
RETRIEVAL → HYBRID SEARCH → RANKING → CONTEXT COMPRESSION → TOKEN/COST
GUARD → LLM/AGENT → RESPONSE/ACTION → VERIFICATION. Required: repository
ingestion; strict user/repository isolation; intelligent code chunking;
symbol extraction (function/class/method/module); semantic search;
keyword search; symbol search; dependency-aware search; hybrid
retrieval; relevance ranking; context compression; incremental indexing;
safe caching; cache invalidation; token measurement; retrieval latency
measurement; retrieval quality evaluation; security and regression
tests. Do not add Vector DB blindly. Evaluate PostgreSQL+pgvector or
alternatives using evidence. Do not sacrifice correctness for token
savings. Measure input tokens with/without retrieval, tokens saved,
context size, latency, quality and estimated cost. Treat repository
content as potentially untrusted/prompt-injection-bearing input. STOP +
approval.
